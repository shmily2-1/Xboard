# 独立前端接口对接（8080）

## 地址
- 本机接口根地址：http://127.0.0.1:8080
- 本机 API Base URL：http://127.0.0.1:8080/api/v1
- 域名 API Base URL：http://dorocloud.net:8080/api/v1（需域名解析到本机且网络放行）
- 如果前端自己拼接 /api/v1，配置中只填 http://dorocloud.net:8080，避免重复路径。

8080 根路径返回 JSON 服务说明，不加载主题。只有 /api/ 路由转交 PHP；主题资源、后台页面及直接 PHP 访问不开放。
原有 80 端口的网站、主题、后台和短订阅链接保持原样。两套入口使用同一数据库和后台服务，不是复制一套网站。

## 常用接口（下列路径相对于 /api/v1）
| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /guest/comm/config | 公开站点配置 |
| GET | /guest/plan/fetch | 公开套餐列表 |
| POST | /passport/auth/login | 登录，JSON 传 email、password |
| POST | /passport/auth/register | 注册，按站点规则提供参数 |
| GET | /user/info | 当前用户资料，需登录认证 |
| GET | /user/plan/fetch | 用户套餐列表 |
| GET | /user/getSubscribe | 用户订阅资料 |
| GET | /user/order/fetch | 订单列表 |
| POST | /user/order/save | 创建订单，会产生业务数据 |
| POST | /user/order/checkout | 发起支付，请由用户确认操作 |

普通数据请求使用 Accept: application/json，JSON 请求加 Content-Type: application/json。
认证接口使用 Authorization 请求头，按登录响应提供的 auth_data 传入；不要把数据库密码写进前端。
沿用项目现有 CORS 配置：允许跨域和 Authorization 请求头，不启用跨域 Cookie 凭据。
客户端订阅下载仍应使用接口返回的订阅地址，不要把文件下载响应一律当 JSON。
8080 不提供 /s/... 短订阅路由；原端口的短订阅地址继续保留。

## 配置文件
- 生效配置：D:\BtSoft\nginx\conf\vhost\dorocloud-api-8080.conf
- 项目副本：D:\wwwroot\dorocloud.net\windows\nginx-api-8080.conf.example
- Windows 防火墙规则：DoroCloud-API-8080（仅 Nginx TCP 8080 入站）

已完成必要检查：8080 根路径及公开接口返回 200，跨域预检返回 204，未登录访问用户接口返回 403，主题访问被拒绝，原站点返回 200。未提交登录、订单或支付请求。

## 公网部署注意
本机访问已可用；公网 DNS、路由器映射、云安全组及运营商端口限制未验证。
当前 8080 是 HTTP，适合本机开发或作为反向代理后端。正式前端请使用带 HTTPS 的 API 域名/反向代理，不要通过公网明文 HTTP 发送账户密码或令牌；HTTPS 前端也不应直接调用 HTTP API。
当前后台 APP_URL、订阅地址和支付回调地址没有改动。更换公开域名时需另外统一这些地址。
